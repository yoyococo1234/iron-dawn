### 3.2 已经修掉的（确认有效）

**① GPU 动画数组超限（最严重）**

```hlsl
float4 _PathArr[256];   // 256 × 4 = 1024 个 float
```

`Material.SetVectorArray` 上限是 **1023 个 float**。1024 超 1 个 → **整个数组静默设置失败**，不报错不警告，顶点着色器读到未初始化数据 → **履带板被甩到随机位置，看起来就是"炸开/卡帧/重复"**。

修法：`_PathArr[255]`，CPU 端把 `b.N`（256）个采样点均匀重采样到 255 个。

**② 尺寸三轴对齐（`VehicleModelBinder.AlignTracks`）**

以前是「按车体高度 × 88% 等比缩放」：轻坦履带本来 7.02 m 长、和车体 7.10 m 正好，被放大 27% 后变成 8.96 m，前后都戳出车体；宽度只有 2.66 m（车体 4.01 m），像一条细铁丝。

改成三轴分开：

| 轴 | 规则 | 为什么 |
|---|---|---|
| X（宽） | 拉伸到车体宽 × 0.98，夹 0.60~2.20 | 沿 X 拉伸**不会**把负重轮压扁（轮子的圆在 YZ 平面） |
| Z（长） | 对齐车体长，夹 0.85~1.20 | 超出会戳出车体，压太狠轮子变椭圆 |
| Y（高） | 车体高 × 0.72，**只允许缩小**（上限 1.00） | 以前允许放大 15%，1.42→1.63 m 顶到侧裙上面 |

**③ `static` 网格里的离群碎片**

履带总成里 Lux3D 留了个 `static` 网格（本该是主动轮/托带轮），混着几十片散在车外飘着的碎面 —— 就是用户看到的"横穿车体的线条"。

用 `work/clean_track_static.py` 处理：拆松散块（87 块），按"离中线太远 / 极薄 / 小于 6 cm"删掉 20 块，存成 `light_tracks3_clean.fbx`（4528 顶点）。

**关键教训：不要整体关掉 `static`。主动轮就在里面，关掉之后履带前端变成空壳 —— 我犯过这个错。**

## 7. 踩坑清单（这一轮新增）

| 坑 | 现象 | 修法 |
|---|---|---|
| `SetVectorArray` 超过 1023 float | 静默失败，shader 读到垃圾数据 | 数组最多 255 个 Vector4 |
| 后处理 shader 的 4 个 Pass 写成单行 | Unity 只认 3 个 Pass，画面全黑 | `Pass{}` 必须展开成多行 |
| `Destroy(collider)` 当帧不生效 | 鱼雷一发射就撞上自己 | 先 `enabled=false` 再 Destroy |
| 武器资产 `isTorpedo` 没打开 | 鱼雷走普通炮弹逻辑 | 开关要和代码一起改 |
| Blender 给碎面片大网格追加顶点 | `EXCEPTION_ACCESS_VIOLATION` 崩溃 | 补面改到 Unity 端程序化生成 |
| `AlignTracks` 按高度等比缩放 | 轻坦履带放大 27% 戳出车体 | X/Y/Z 三轴分开对齐 |
| 整体关掉 `static` | 主动轮没了，履带前端空壳 | 只删离群块，保留主体 |
| 工具调用间隔十几秒 | 误判"鱼雷发射就消失"（其实走完射程了） | 用 `timeScale=0.05` 慢动作验证 |
| Unity 恢复场景备份 | 弹窗要点 Yes，之后 MCP 可能连不上 | 等 60~90 s 再 `mcp_switch_on unity` |
| 我的截图 ≠ 用户看到的 | 用户三次说"不一样" | 用游戏内实际机位截图验收 |
