## 2. 这一轮做完的事

### 2.1 主战炮塔：先对准 → 再重做 → 最后重新生成（走了三段）

1. **先按实测座圈把 pivot 对准**（提交 7e57b94）。量出座圈圆心 (0.001, 0.283)、半径 1.180、
   甲板 2.400；同时量出炮塔网格的俯视轮廓质心相对自身原点偏 +0.337 —— 也就是说
   **「炮塔看着偏右」不是 pivot 数字错了，是炮塔网格本身不对称**，pivot 怎么调都不可能同时
   满足「塔体居中」和「炮口居中」。
2. **Blender 重做 v6**（提交 c07ff75）：塔体本体相对炮管歪 **+37°**、炮管轴线又比塔体偏
   **16.5°**。用「面片质心最小面积包围盒」求塔体朝向先摆正，再**迭代拟合炮管真实轴线**
   （粗扫描 233.5° → 拟合 187.7°），按轴线切脖子、把炮管转正，最后塞进炮盾。
   work/prep_turret_v6.py。
3. **最后按用户要求重新生成**（提交 1d0073f）：旧炮塔是开底壳、越往下越细，补丁怎么打都丑。
   用 Lux3D **只生成炮塔**（task 4587498，20 积分），提示词要求「不要炮管、平底全宽、
   竖直侧壁」，按宽度缩放到 **2.4 m**（座圈实测 2.36），炮管按中线手工摆上去。
   work/prep_turret_only.py。

### 2.2 重装坦克：程序化履带 + 炮塔重新生成

- **剥自带履带**：`work/strip_tracks.py`，裙板下沿在车高 34%（z=1.300）、车体侧壁到 |x|=1.802，
  删掉 `z<1.30 且 |x|>1.802` 的面（16540 / 59589）→ `heavy_v6_hull.fbx`
- **实测履带规格**（之前那组是估的）：span 2.42 / band 0.88 / loop 9.80×1.30 / 轮 R0.45 ×6
- **新增 `VehicleDef.trackDrop`**：剥完履带后车底比原履带底面高 **0.948 m**，而程序化履带是
  按「底面=车体原点」生成的，不下沉就整体浮在车底那一层。`BuildProcedural` 里把 Tracks 节点
  放到 `localPosition=(0,−trackDrop,0)`。重装 trackDrop=trackGroundLift=0.948。
  实测履带底面离地 −0.028 m（主战是 −0.036，一个量级）。
- **炮塔重新生成**（task 4586782，20 积分）：同主战那套，宽度缩放到 **3.9 m**（座圈 3.93）。

### 2.3 炮塔「后脑勺是空的」

Lux3D 生成的炮塔是**开底壳**，外壳下沿高低不齐，从车后下方能直接透过塔体看到天空。
Unity 那边的 `TurretBaseCap` 圆盘是按「炮塔短边 × 0.55」算半径的，比塔体本身还宽
（主战 2.64 对 2.40、重装 4.29 对 3.90），反而露出一圈台阶裙边。

最终做法：
- 炮塔网格按**俯视轮廓**生成一块**双面**底板（单面从上方看会被背面剔除，等于没补）
- 两台车的 `autoTurretSkirt` 都设成 **0**（塔体自己有底了，那个圆盘只会添乱）

> 试过但**没采用**：沿轮廓拉一圈「内壁裙边」堵外壳下沿的缝 —— 外壳下沿高低不齐，
> 墙会从外壳下面一段一段露出来，比原来更难看。

### 2.4 按住 C 环视

- **坦克/炮艇**：本来就好的。`PlayerTankController` 里「直接瞄准」那段以前没判 freeLook，
  导致按 C 时炮塔仍被相机 yaw 拖着转，已补上 `!freeLook`（提交 36c69fb）。
- **飞机**：`CameraFollow.LateUpdate` 里飞机走的是单独分支
  `if (pl.Def.domain == Domain.Air) { ChaseCamera(); return; }`，**在 C 环视代码之前就 return 了**，
  所以飞机一直没有环视。已改成先判 C：不按 C 照旧追尾，按住 C 用 `OrbitAroundTarget()`
  绕飞机转；并新增 `CameraFollow.FreeLookActive`（static），`VehiclePhysics.UpdateAir`
  读到它时**不再把鼠标累加到飞机操控上**（否则一边转镜头一边把飞机拐走）。

### 2.5 飞机机头进气口涡轮风扇

Lux3D 的飞机是**单网格**，进气口就是个黑窟窿，模型里没有可旋转的叶片。新增
`Assets/Scripts/Units/JetIntakeFan.cs` 程序生成：整流锥 + **9 片 28° 扭角叶片** + 一根
往后插进进气道的**发动机轴**，转速跟空速（怠速 260°/s，满油门约 2520°/s ≈ 7 圈/秒）。

位置写在 `VehicleDef.intakeFans`（Vector3[]，车体局部坐标，米，Y 上 Z 前）+
`intakeFanRadius`。实测唇口在 z≈5.17、内壁在 z≈3.98，所以风扇放在 **z=4.85**（唇口往里 0.32）。

### 2.6 滚轮缩放

飞机的镜头分支以前在滚轮代码之前 return，所以飞机上滚轮完全没反应（坦克是好的）。
飞机分支补上 `distance = Clamp(distance − scroll*zoomSpeed, 10, 70)`，追尾和环视都吃。

### 2.7 战斗机机头两根棍子

Lux3D 自带的小 greeble（进气口下沿、x≈±0.1、y≈1.0、z≈4.9~5.5），已删。
`work/cut_faces_box.py` 按面中心框选，命中 488 面 / 57520 → `air_fighter_v2.fbx`。

## 5. 这一轮踩的坑（下一个人别重复）

1. **坐标换算的符号一定要先用「命中数」验证**。`cut_faces_box.py` 里写的是
   Unity(x,y,z前) → Blender(x,−z,y)，但实测**符号是反的**（实际 Unity z = +Blender y）。
   第一次传正值，切的是机尾，机头那两根棍子一直在，白折腾三轮。
   判据：同一个盒子，传 z 负命中 488 面、传正只命中 33 面 —— 一眼就能看出来。
2. **别用 PowerShell 的 `Set-Content` 改 Python 脚本**。PS 5.1 默认按 GBK 读 UTF-8，
   写回去就把中文注释全变成乱码，`prep_turret_v6.py` 当场语法错误、差点丢掉。
   改脚本一律用 `edit` / `write` 工具。
3. **双面几何必须错开 3 mm**。底板/侧壁正反两片完全重合会 z-fighting，渲染出来是一条条竖条纹。
4. **单面底板等于没补**。Unity 用背面剔除，朝下的板从上方看直接消失 —— 必须正反两份。
5. **别指望「按连通块删」能删掉焊在主体上的东西**。飞机那两根棍子是焊在进气口下唇上的，
   属于同一个大连通块，只能按面框选。
6. **测进气口/炮管这类「洞」的位置，用射线扫比看图靠谱**。图上看是「戳在机头前面」，
   射线一打才知道它其实在唇口里面 0.3 m。
7. **改完 Unity 资源要等一帧再读**。`script-execute` 是阻塞的，设完标志立刻渲染，
   `LateUpdate` 还没跑过，读到的还是旧值 —— 要分两次调用、中间 `Start-Sleep`。
