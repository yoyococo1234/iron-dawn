## 1. 【未修好】Esc 只退出"等新键"这一层，不该退出整个按键设置

### 用户原话

> 按 Esc 只退出编辑模式没改明白，我是让你退出选择新按键这个阶段，不是退出一整个按键设置，你仍然没做好

### 我已经做了什么（在 `5f46aa5`，包 f 之后都有）

```csharp
// MenuKeys.cs
public static bool IsWaiting => _waiting.HasValue;

// 捕获分支
if (e.keyCode == KeyCode.Escape) { _waiting = null; Say("已取消", UiKit.Dim); e.Use(); }

// GameStartScreen.cs:68
if (_page != Page.Main && !MenuKeys.IsWaiting && Input.GetKeyDown(KeyCode.Escape)) _page = Page.Main;
```

### 为什么**它还是没有效**（待现场确认，不是结论）

按代码顺序推演是应该对的：Update 先跑（此时 `IsWaiting == true` → 守卫挡住），
OnGUI 后跑（`MenuKeys.Draw` 把 `_waiting` 清掉）。但用户实测仍是整块面板退出，
说明这条推演至少有一个前提不成立。**下次开工按这个顺序查**：

1. 在 `GameStartScreen.Update()` 和 `MenuKeys.Draw()` 各打一行日志
   （`Debug.Log($"page={_page} waiting={MenuKeys.IsWaiting} esc={Input.GetKeyDown(KeyCode.Escape)}")`），
   先确认**同一帧里两者的先后与取值**，别猜。
2. 确认 `GameStartScreen.Update()` 里 line 68 **之前**有没有别的 `return`
   （重写主菜单时把 `_paused` 相关逻辑改动过，早期 return 会让守卫整段失效 —— 但那种情况是"面板关不掉"，
   和用户描述相反，所以更可能是别的原因）。
3. 确认 `MenuKeys.Draw` 真的被调用（`_page == Page.Keys` 且 `_pageAnim` 没把它挡住）。
4. **最可能的坑**：`Event.current.type == EventType.KeyDown` 的 KeyDown 事件在 IMGUI 里
   可能被 `UiKit.Button` 之前的某个 `e.Use()` 吃掉（面板里 15 个按钮 + 浮层都在同一帧跑）。

### 推荐的根治写法（下次直接采用，别再打补丁）

**只留一个 Esc 入口**，把"要不要关面板"的判断也放进 MenuKeys，主菜单不再自己读键盘：

```csharp
// MenuKeys.cs
static bool _back;                       // 由内部请求返回主菜单
public static bool ConsumeBack() { if (!_back) return false; _back = false; return true; }

// Draw() 捕获分支里：
if (e.keyCode == KeyCode.Escape)
{
    if (_waiting.HasValue) { _waiting = null; Say("已取消", UiKit.Dim); }  // 第一层：取消改键
    else { _back = true; }                                                 // 第二层：返回主菜单
    e.Use();
}

// GameStartScreen.Update()
if (_page == Page.Keys && MenuKeys.ConsumeBack()) _page = Page.Main;
```

这样"Esc 的两层语义"由**同一个函数**按顺序判定，不存在两个组件抢同一个按键。

## 3. 【设计疑问·已查清】在车库等 3 分钟会开放飞机吗？

**答：不会。整个对局是暂停的。**

依据（读代码确认，不是猜）：

| 位置 | 事实 |
|---|---|
| `GarageScreen.Open()` | `Time.timeScale = 0f` |
| `MatchManager.Update()` | `timeLeft -= Time.deltaTime;` → 暂停时 `deltaTime == 0`，对局时间不走 |
| `MatchSettings.MatchElapsed` | `= matchTimeLimit*60 - timeLeft` → 跟着 `timeLeft` 走，所以**冻结** |
| `MatchSettings.DomainUnlocked` | 读 `MatchElapsed` → 冻结 → 飞机不会开放 |
| `UpdateRespawns()` | 用 `Time.time`（timeScale=0 时也不走）→ AI 也不会复活/出场 |

所以「选载具界面等 3 分钟」和「按 G 回车库等」都是**全暂停**：AI 停、炮弹停、计时停、解锁停。

**但有两点值得下次和用户确认（这是设计问题，不是 bug）：**

1. **玩家可以无限期停在车库** —— 相当于一个免费的全图暂停。开局不利就挂机，AI 也不会推进。
   要不要给车库加个"最多停 20 秒"的倒计时？
2. **解锁计时用"对局时间"还是"真实时间"** —— 现在是对局时间（公平、但不能靠挂机刷）；
   如果用户期望"挂够 3 分钟飞机就开"，那是另一套语义，要显式改。

## 4. 【待修·手感 bug】舰艇：不开镜时 Ctrl 锁定很好，**开镜后瞄不准**

### 现象

用户：舰艇，Ctrl 锁定 + 开镜（Shift）→ 准星对不上目标；不开镜用 Ctrl 是好的。

### 代码现状（`PlayerTankController.cs:96-125`）

锁定路径确实会把炮塔/镜头拉向目标：

```csharp
Vector3 lockAim = LockOnSystem.AimPointFor(_combat);
Vector3 muzzle  = _combat.transform.position + Vector3.up * 2.5f;
Vector3 bdir    = ballistic ? VehicleCombat.BallisticDir(muzzle, lockAim, bspd) : (lockAim - muzzle).normalized;
wantYawWorld = Mathf.Atan2(bdir.x, bdir.z) * Mathf.Rad2Deg;
wantPitch    = _lockPitch;
camFollow.yaw   = MoveTowardsAngle(camFollow.yaw, wantYawWorld, ...);
camFollow.pitch = MoveTowards(camFollow.pitch, wantCamPitch, ...);
```

### 最可能的真因（下次先验这条）

**炮管俯仰用的是「鼠标 pitch」的线性反解**：

```csharp
float wantPitch = -(camFollow.tankLookDownDeg + (camFollow.pitch - 8f));   // 非锁定分支
```

这是"屏幕中心射线 → 炮管仰角"的一个近似映射，**只在不开镜、FOV=正常值时成立**。
开镜时 `CameraFollow` 会把机位贴到炮口后面、FOV 收到很小（炮镜分划是固定形状），
此时"屏幕中心代表的世界俯仰"和 `camFollow.pitch` 已经不是线性关系 →
**准星（分划中心）和炮管实际指向分成两条线**。

锁定分支里又反过来去改 `camFollow.pitch`（`wantCamPitch = -wantPitch - tankLookDownDeg + 8f`），
和开镜的机位解算互相打架 —— 表现为"锁定了但还是偏"。

### 排查步骤（按顺序）

1. 开镜 + 锁定时，把 `wantYawWorld / wantPitch`、`camFollow.yaw / pitch`、
   相机实际 `transform.forward`、炮管实际朝向各打一行日志，**对比这四组数**。
2. 看 `CameraFollow` 里开镜分支（`_scoped`）是不是**完全接管**了相机朝向；
   如果是，那 `camFollow.pitch` 就只是"鼠标过去累计的意图"，不能再当炮管仰角源。
3. 正确解法方向：**开镜时炮管仰角直接来自锁定目标的世界方向**（`bdir`），
   不要经过 `camFollow.pitch` 反解；也就是开镜 + 锁定时走 `wantYawWorld/wantPitch` 这条，
   不要被 `wantPitch = -(camFollow.pitch ...)` 覆盖。检查两个分支的执行顺序与条件。

## 5. 【待修·手感 bug】舰艇的机枪"索敌"问题很大，瞄不到人

### 代码现状

- 机枪是**独立回转座**：`SetDeckGunYaw(relYaw, mgTurnSpeed)`，
  基准是 `turretWorldYaw = 船体yaw + turretYaw`，并且**机枪模式不转炮塔**（`PlayerTankController.cs:127-136`）。
- 机枪限位：±120°（`SetDeckGunYaw(0f, 120f)` 归位那次用的就是 120 这个量级）。
- 锁定目标筛选 `LockOnSystem.PickTargetInCone`：机枪模式把锁定距离压到 `min(机枪射程, 600f)`，
  并且用 **屏幕坐标** 判锥角（`sx = |sp.x/Screen.width - 0.5|`），先试 22°，失败再试 45°。

### 三个可疑点（每个都可独立验证）

1. **±120° 限位 + 炮塔不转**：机枪只覆盖"炮塔当前朝向 ±120°"。
   船在转向时，炮塔朝向不会跟着机枪视野走，视角一转目标就出了限位 → 枪架卡死、打不到。
   **验法**：机枪模式下原地把视角转到船正后方，看枪架是不是卡在某角度。
2. **锁定距离被压到 600 m**，而舰炮能打 1200 m。
   玩家在 800 m 用机枪按 Ctrl，**锁不上**（不是"锁了打不中"）。
   **验法**：在 700~900 m 处按 Ctrl，看有没有锁定框。
3. **开火点用屏幕射线、枪管朝向用另一个解算**：
   `_combat.FireDeckGunAt(CameraAimPoint())` —— 子弹从**枪口**朝**屏幕点**飞，
   而枪架角度是 `relYaw/wantPitch` 另算的。两者不一致时，视觉上"枪口朝前、子弹斜飞"，
   命中判定用的是射线所以有时能中、有时打空气。
   **验法**：对着 100 m 的墙开一枪，对比弹着点与准星。

### 建议方向（下次再定，别急着改）

- 机枪"索敌"其实是**锁定逻辑**的问题，不是弹道：先让机枪模式有独立的、以**枪架朝向**为基准的
  目标筛选（锥角 ±60°、距离按机枪射程），锁定后**把枪架转到目标**（和炮塔那套一致）。
- 或者更简单：机枪模式解除 ±120° 限位里的"以炮塔为基准"，改成以**船体**为基准。
