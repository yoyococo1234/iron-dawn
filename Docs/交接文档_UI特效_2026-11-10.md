今天最值钱的两条是：
- §5 第 5 条：`GUIUtility.RotateAroundPivot` 在缩放过的 `GUI.matrix` 下会把线段甩出画面（命中标记、锁定断弧都栽了）。

## 2. UiKit API 速查（写新界面照抄这段）

### 2.1 坐标系与缩放

```csharp
var oldMatrix = UiKit.BeginScaled(out float scale, out float vw);  // 切到 1080 高的虚拟画布
var mouse = UiKit.Mouse(scale);                                     // 鼠标的虚拟画布坐标
...
UiKit.EndScreen();          // 收尾：复位透明度 + 画涟漪和浮字
GUI.matrix = oldMatrix;     // 还原
```

所有坐标按 **1080 高**写（`vw` 一般是 1920，超宽屏会更大）。720p ~ 4K 都不会错位。

### 2.2 配色（直接用，别新造颜色）

`UiKit.Gold` 金（强调/价格/键帽）、`Ally` 蓝（我方）、`Bad` 红（敌方/危险）、`Good` 绿（健康）、
`PanelBg` / `PanelHover` 面板底、`Edge` 描边、`Text` 主文字、`Desc` 说明、`Dim` 次要、`Mute` 禁用。

### 2.3 画图形

| 方法 | 用途 |
|---|---|
| `Box(r, c)` | 实心矩形（`Texture2D.whiteTexture` + `GUI.color`） |
| `Frame(r, c, t=1)` | 描边 |
| `VGradient(r, top, bottom, steps=0)` | 垂直渐变（**只用于两端颜色不同**；叠照片上会出横线，见 §11.3） |
| `HGradient(r, left, right, steps=0)` | 水平渐变（同上，只用于不同色） |
| `FadeDown(r, c)` | 区域**顶部**不透明、向下淡出（单张贴图一次画，**无接缝**） |
| `FadeUp(r, c)` | 区域**底部**不透明、向上淡出 |
| `FadeRight(r, c)` / `FadeLeft(r, c)` | 左/右方向的同色淡出 |
| `Vignette(vw, strength, band)` | 四边暗角（内部用上面四个 Fade） |
| `PhotoBackdrop(vw, tex, darken, topFade, bottomFade, vignette)` | **实景背景**：铺图 → 压暗 → 冷调 → 上下渐变 → 暗角；tex 为 null 自动退回纯渐变 |
| `Blob(r, c)` | 径向光晕（64² 运行时生成贴图），给缩略图当背光 |
| `Backdrop(vw, alpha)` | 纯渐变底（没有实景图时的退路） |
| `Card(r, hover)` | 标准面板：底 + 顶部高光条 + 细描边（hover 时描边变金） |
| `HLine(x, y, w, a=0.13)` | 分隔线 |
| `Chip(r, s, c, size=16)` | 小标签（淡底 + 同色描边） |
| `KeyCap(r, key, size=18)` | 金色键帽 |
| `Bar(r, t, c)` | 数值条（底槽 + 填充） |
| `Heading(vw, y, title, sub, size=46)` | 页面大标题 + 金色短横 + 副标题，返回占到的底部 y |
| `Label(r, s, size, c, anchor, bold)` | 文字（按字号/对齐/粗细缓存 GUIStyle，不每帧 new） |

### 2.4 交互（**这是今天补上的那一层**）

```csharp
var hit = UiKit.Button("garage_" + def.displayName, slot, mouse, enabled);
//   id       —— 每个控件唯一且稳定（同一帧里重复 id 会互相打架）
//   slot     —— 命中区（不要传动画后的矩形）
//   enabled  —— false 时点击会抖动 + 拒绝音，用来做"买不起"的反馈
// 返回 Hit { hover01, hover, pressed, clicked, denied, shake }

var r = UiKit.Lift(slot, hit);      // 悬停上浮 3px / 按下沉 2px / 拒绝时左右抖
UiKit.Glow(r, hit.hover01, UiKit.Gold);  // 悬停外发光（画在卡片之前）
if (hit.clicked) { ... }            // 按下和松开都在区域内才算点击
else if (hit.denied) UiKit.Float("金币不足", pos, UiKit.Bad);
```

- `Button` 内部会 `Event.current.Use()`，**点完不要再自己判断鼠标**。
- 悬停淡入淡出、按下/松开配对、涟漪、音效全在里面，调用方只管 `clicked / denied`。
- `hover01` 是 0..1 的平滑值，做插值高亮用它；`hover` 是瞬时 bool，做文案切换用它。

### 2.5 动效与浮层

| 方法 | 用途 |
|---|---|
| `Anim(ref state, open, speed=6.5)` | 开合进度 0..1（开 6.5/s 推进、关自动回落），**在 OnGUI 里调，内部只在 Repaint 推进** |
| `PopIn(r, k)` | 按开合进度把面板从略小（0.94）、略低（+18px）处弹出来 |
| `Fade(k)` | 设整体透明度乘子 |
| `Float(s, p, c)` | 浮动文字（金币 ±N / 买不起原因），0.9 s 上浮 40px 淡出 |
| `Smooth(t)` | smoothstep，`t*t*(3-2t)` |
| `Blocking` | 有没有界面挡在战斗前面（开火/锁定/抢光标都要先问它） |
| `SwallowInput(sec=0.3)` | 界面关掉后继续吞掉鼠标这段时间（防"点出击顺手开一炮"） |

### 2.6 一个面板的标准骨架

```csharp
float _anim;   // 字段：开合进度

void OnGUI()
{
    float k = UiKit.Anim(ref _anim, IsOpen);
    if (!IsOpen && k <= 0.001f) return;      // 关掉后还要多画 0.15 s 淡出

    var oldMatrix = UiKit.BeginScaled(out float scale, out float vw);
    var mouse = UiKit.Mouse(scale);
    bool live = IsOpen;                      // 淡出期间不再响应点击

    UiKit.Fade(k);
    UiKit.Box(new Rect(0, 0, vw, 1080f), new Color(0.01f, 0.015f, 0.025f, 0.62f)); // 压暗
    var panel = UiKit.PopIn(new Rect(vw*0.5f - 380f, 540f - 250f, 760f, 500f), k);
    UiKit.Card(panel);

    // ... 内容，可点的地方用 UiKit.Button ...

    UiKit.EndScreen();
    GUI.matrix = oldMatrix;
}
```

## 3. 硬约束（不看必踩，都是今天实测踩过的）

1. **OnGUI 一帧会跑 3~4 遍**（Layout / Repaint / 各种事件）。
   任何"推进状态"的代码必须放在 `Update()`，或包在 `if (Event.current.type == EventType.Repaint)` 里。
   放错地方的表现是：动画快 3~4 倍、音效一帧响好几次。
2. **界面打开时 `Time.timeScale = 0`**，`Time.deltaTime` 是 0。
   界面里的动画一律用 `Time.unscaledDeltaTime` / `Time.unscaledTime`。
3. **`UiKit.Alpha` 是全局乘子**，`Fade()` 改它，`Box/Frame/Label/...` 都会乘进去。
   **每个界面画完必须调 `EndScreen()` 复位**，否则下一个界面跟着变透明。
4. **涟漪和浮字一帧只画一次**（`FxOnce` 按 `Time.frameCount` 去重），所以多界面同帧调用不会重复叠色。
   它们的坐标是**虚拟画布坐标**，必须在 `GUI.matrix` 还是缩放状态时画（`EndScreen()` 要放在还原矩阵之前）。
5. **`UiKit.Button` 会吃掉鼠标事件**。同一个矩形上不要再写 `Event.current.type == MouseDown` 的判断。
6. **`Lift` 只移动绘制，不移动命中区**。命中判断永远用原始矩形，否则悬停时控件会在鼠标下"跑掉"、点击丢失。
7. **半透明横条不能重叠**：`VGradient` 里坐标必须 `Mathf.Round` 且首尾相接，否则 alpha 叠加出横纹。
8. **界面关闭必须 `SwallowInput()`**，否则关界面的那一下左键会被战斗当成开火。
9. **`UiSound` 走独立 AudioSource 且 `ignoreListenerPause = true`**，暂停（`AudioListener.pause`）时界面音效照样响。

## 4. 今天改了什么（按文件）

### 4.1 `UiKit.cs`（+约 40 行）

- 新增 `Alpha`（全局透明度乘子）+ `A(Color)` 私有函数，`Box` / `Label` 都过它 → 面板淡入淡出不用手算每个颜色
- 新增 `EndScreen()`：复位 `Alpha` + 画涟漪 + 画浮字（各界面收尾统一调这一个）
- `Fade(k)` 从"设 `GUI.color`"改成"设 `Alpha`"（原来的写法会被 `Box` 里的 `GUI.color = c` 覆盖掉，等于没生效）
- `DrawRipples` / `DrawFloaters` 加 `FxOnce` 帧去重，`Event.current` 判空

### 4.2 `GarageScreen.cs`

- 卡片从"手写 hover + MouseDown"改成 `UiKit.Button` + `Lift` + `Glow`
- 面板开合动画（`Anim` + `PopIn` + `Fade`），关闭后继续画 0.15 s 淡出
- 点不起时卡片抖动 + 拒绝音 + `Float("金币不足")`
- `Open()` / `Close()` 加开关音效；`Close()` 加 `SwallowInput(0.35f)`
- 排版：武器行高度 24 → 42（允许两行），简介下移 176 → 192

### 4.3 `ShopScreen.cs`

- 商品行改成 `UiKit.Button` + `Lift` + `Glow`
- 购买成功：`-N` 金币浮字 + 金币音；点不起：浮字说明原因
- 面板开合动画；`Update()` 里开关时播开关音 + `SwallowInput(0.3f)`
- 面板高度 `168 + n*92 + 56` → `140 + n*92 + 46`（原来底下空 80 px）

### 4.4 `PauseScreen.cs`

- 重构成 `Toggle()` 一个入口（P 键和面板按钮共用）
- 面板开合动画；暂停时主动放开光标
- 第一行「P 继续战斗」变成**可点按钮**（悬停变金 + 右侧「点击继续 ›」）

### 4.5 `GameStartScreen.cs`

- 入场淡入：`_fade` 用 `unscaledDeltaTime` 推到 1，最后压一层黑 `alpha = 1-fade`
- 标题金色光晕**呼吸**（`0.16 + 0.16*Sin(unscaledTime*2.1)`），原来是一层静态光晕，像贴纸
- 缓慢下移的扫描光带（14 条 5px 半透明带，周期约 13 s）
- `Begin()` 加确认音 + `SwallowInput(0.35f)`

### 4.6 `PlayerTankController.cs` / `CameraFollow.cs`

- `PlayerTankController.Update()` 开头加 `if (UiKit.Blocking) return;` —— 界面挡着时整段战斗输入跳过（瞄准、开火、切武器、机枪模式全不响应）
- `CameraFollow.Update()` 里"点一下重新锁光标"的判断加 `!UiKit.Blocking` —— 否则在面板上点一下光标就被抢走

### 4.7 `MatchHUD.cs`（+约 220 行，五个战斗特效）

| 特效 | 实现要点 |
|---|---|
| **命中标记** | `ShowHitFeedback(HitResult)` 签名不变，内部改记 `_hitKind` + `_hitAt`（unscaledTime）；准星处四角 45° 斜线各 14 px + 中心点，0.28 s 内缩放 1.35→1.0、alpha 1→0；击穿金、未击穿/跳弹红 |
| **位置跟准星** | 新增 `MarkCross(x, y)` / `_crossPos` / `_crossFrame`，`DrawCrosshair` 每帧把准星位置记下来；命中标记画在那个位置，本帧没画准星才退回屏幕中心（**陆战准星是炮口投影，可能贴边，画在正中会让人以为打偏**） |
| **受伤红边** | 四边**互不重叠**（上下满宽、左右只画中段）各 14 条细分按平方衰减；掉血 0.5 s 脉冲，血量 < 30% 时 `Sin(unscaledTime*2.2)` 常驻脉动，两者取 `Max` 不相加 |
| **金币浮字** | 金币变化时在金币面板右侧浮 `+N` / `-N`，0.9 s 上浮 40 px 淡出，上限 6 条 |
| **击杀提示入场** | 新条目 0.18 s 从 +40 px 滑入 + 淡入，旧条目按 age 缓动让位，老逻辑 4 s 后 2 s 淡出不变 |
| **结算面板入场** | 0.4 s 内 0.94→1.0 缩放 + 淡入，标题「胜利/失败」额外 1.0→1.08→1.0；全屏压黑**不**跟着缩放（跟着缩会漏出四边战场） |

**关键实现约束**：血量差 / 金币差 / 结算时刻 / 浮字清理全部在 `Update()` 里的 `PollCombatFx()` 做，
而且必须放在原来那个 `if (Time.time < _radarNextScan) return;` **之前**，否则轮询频率掉到 6.7 Hz。
`OnGUI` 里只有纯读绘制。

## 8. 血泪教训（这次新增的）

1. **`GUI.matrix` 有缩放时不要用 `GUIUtility.RotateAroundPivot`**（§5 第 5 条）。
2. **`Fade()` 别用 `GUI.color` 实现**：`Box` 内部会 `GUI.color = c` 覆盖掉，等于没生效。要一个乘子。
3. **"写了但没接线"是最常见的半成品**：这次发现的现状就是 `UiKit` 的交互层（Button/Lift/Glow/涟漪/浮字/Blocking）全写好了，
   但四个界面一个都没调，界面还是各写各的 hover。**改完 UI 先 grep 一遍有没有人调你的新 API**。
4. **截图比肉眼看代码可靠**：5 个 bug 里 3 个（武器行重叠、弹药/提示重叠、常亮装填条）肉眼读代码完全看不出来，
   一截图立刻现形。**改完界面必须截图**。
5. **自动截图测试要防"人被 AI 打死"**：这次好几次截图抓到的是车库/结算面板，因为测试期间玩家被 AI 打死了。
   做法：截图前 `p.hp = p.maxHp`，或先 `MatchManager.Instance.unlimitedLives = true`。
6. **`ScreenCapture.CaptureScreenshot` 是帧末写盘**，`await Delay(≥100ms)` 才读得到新文件。
7. **`GUI.matrix` 有缩放时，逐条拼的半透明矩形必然出接缝**（§11.3）：露缝就亮线、重叠就暗线。
   压暗/淡出一律用单张贴图（`FadeDown/FadeUp/FadeLeft/FadeRight`）。
8. **排查视觉 bug 要"先验素材、再验 UI"**：这次先逐行扫源 PNG 确认干净，再用"每 16px 一次突跳 + 缩放比 1.3333 → 12 虚拟像素"锁定接缝周期，
   一次就定位。凭感觉改参数只会越改越乱。

## 10. 载具缩略图（2026-11-10 晚补）

### 10.1 做了什么

车库原本是六张**纯文字卡片**，像表格不像游戏。现在每张卡片顶部有一条车图（透明底 PNG）+ 按域着色的背光光晕，
观感差别见 `Docs/UI_车库_20261110.png`（纯文字）对比 `Docs/UI_车库_带缩略图_20261110.png`。

- **生成器**：`Assets/Editor/UiThumbGen.cs`
  - 菜单 `Tools → 铁皮黎明 → 生成载具缩略图`，或 `UiThumbGen.Generate()`（可在 MCP `script-execute` 里直接调）
  - **不手搓模型**：直接调 `VehicleModelBinder.Attach(root, def, out _, out _)` —— 和游戏里完全同一套车体/炮塔/履带装配 + 材质替换
  - 临时根节点挪到 `y = -3000`（附近什么都没有，不用改图层），一台临时相机 + 主光/补光渲到 RenderTexture，读像素存 PNG
  - 输出 `Assets/Resources/UiThumbs/<VehicleDef 资产名>.png`，**1000×300（10:3）透明底**
  - 导入设置由脚本自动改：不压缩、无 mipmap、`alphaIsTransparency`
- **运行时**：`GarageScreen.Thumb(def)` 用 `Resources.Load<Texture2D>("UiThumbs/" + def.name)` 取，缓存进静态字典（找不到也缓存 null，否则每帧 Load）
- **画法**：`UiKit.Blob()`（新增，64² 径向渐变贴图，运行时生成一次）做背光；车图 `ScaleMode.ScaleToFit`；底边压一层渐变融进卡片底色
- **卡片布局**：高度 330 → 370，顶部让出 120 px 给图带，其余内容整体下移

### 10.2 这个生成器踩的四个坑（改之前先看）

| 坑 | 现象 | 真因 | 修法 |
|---|---|---|---|
| **按包围盒 8 个角取景** | 车只占画面 57%，四周大片空白 | 坦克车体是楔形，包围盒的角是**空气**；约束永远由"空角"决定（实测某个空角要求 d=16.7，车实际只要 8） | 改成把**所有顶点**投到相机空间取 |x|/|y| 极值（顶点多时按步长采样 4000 点） |
| **取景公式符号写反** | 车偏小、偏在一边 | 屏幕约束是 `d >= |x|/tanH - local.z`，我写成了 `+ local.z` | 按约束推导，别凭直觉 |
| **只算一次距离** | 炮艇左边只剩 20 px、右边空 190 px | 3/4 视角下**投影轮廓中心** ≠ 世界包围盒中心 | 迭代两次：第一次求距离并记下轮廓在相机空间的 x/y 范围，第二次先把中心挪到轮廓中心再重算 |
| **灯光过曝** | 车体几乎全白、细节全丢 | 主光 1.25 + 补光 0.55 + 环境光 0.42 太亮 | 压到 0.92 / 0.34 / 0.30；阴影关掉（透明底上出现投影很脏） |

另外：`VehicleModelBinder.Attach` 内部用 `Object.Destroy`，在编辑器里跑会刷
`Destroy may not be called from edit mode!` 警告 —— **不影响结果**，一次性渲染无所谓，别去改它（那是运行时逻辑）。

### 10.3 还能怎么改进

- 车图现在按高度填满、左右留白（因为卡片图带是 3.3:1，而车本身接近 2:1）。想更大就**加高图带**（卡片再高 20~30 px），
  或改 `ScaleMode.ScaleAndCrop` 裁掉图片上下留白（注意别切掉炮塔顶/履带底）。
- 想更"游戏"一点可以给每张图加地面接触阴影（现在没有，车是"浮"在光晕里的）。
- 攻击机那张图上有一块很亮的高光，是模型自身贴图/法线的问题，不是渲染 bug。

## 11. 实景背景：封面 + 车库（2026-11-10 晚补）

### 11.1 做了什么

封面和车库原来是**纯渐变 + 暗角**，素得像 PPT 底板。现在两者都换成**真实战场的暮色渲染图**：

| 界面 | 图 | 机位 | 分辨率 | 处理 |
|---|---|---|---|---|
| 开局封面 | `UiBackdrops/cover.png` | 城区斜上方 `(560,230,340)` 看向 `(0,40,-260)`，FOV 46 | 1920×1080 | 压暗 0.50 + 冷调 + 上 200 / 下 240 渐变 + 暗角 0.34 |
| 车库 | `UiBackdrops/garage.png` | 街头仰视高楼 `(-300,70,60)` 看向 `(180,40,-430)`，FOV 55 | **480×270** | 压暗 0.62 + 下渐变 0.88 + 暗角 0.40 |

车库那张故意只渲 480×270：**靠双线性放大做出"虚化景深"的假象**，比真跑景深便宜得多，而且和前面的卡片内容形成层次。

效果对比：`Docs/UI_封面_实景暮色_20261110.png`、`Docs/UI_车库_实景背景_20261110.png`。

### 11.2 生成器：`Assets/Editor/UiBackdropGen.cs`

```
Tools → 铁皮黎明 → 生成界面背景              # 正式出图（封面 + 车库）
Tools → 铁皮黎明 → 生成界面背景（候选机位）    # 白天 6 个机位 → work/backdrops，挑构图
Tools → 铁皮黎明 → 生成界面背景（暮色候选）    # 黄昏 6 个机位 → 同上
```

- 直接在 `Map_Battlefield` 场景里摆**临时相机**（`clearFlags = Skybox`，用场景自己的天空盒，氛围才连得上），
  渲到 RenderTexture 读像素存 PNG，用完销毁，**不改场景**。
- 暮色是靠 `Dusk()` 临时改：`Sun` 转到 `(9, -128, 0)` 贴地平线的暖阳、强度 1.15、颜色 `(1,0.62,0.36)`；
  `Sun_Fill` 压到 0.18；环境光改冷蓝 `(0.16,0.19,0.28)`；指数平方雾 `(0.20,0.22,0.30)` 密度 0.0016。
  `DuskState.Restore()` 在 `finally` 里还原 —— **渲染完场景必须和进来时一模一样**。
- 为什么用暮色而不是白天：白天实景太亮太花，UI 压不住；暮色的冷蓝正好和 UI 的深蓝底 + 金色强调同调，
  而且地平线有一道暖逆光，天际线剪影天然好看。

### 11.3 【重要】压暗不能用「多条色条拼渐变」

**现象**：封面顶部出现间隔 16 px 的横向暗线，整片像 CRT 扫描线；渐变过渡是一格一格的。

**排查过程**（照这个顺序，别瞎猜）：
1. 先验源图：直接对 `cover.png` 逐行取亮度，**一个跳变都没有** → 排除渲染图和雾的量化。
2. 再验 UI：对截图逐行取亮度，发现 **每 16 设备像素一次、delta 8~11 的突跳**，且跳变处变亮/变暗有规律。
3. 换算：`Screen.height/1080 = 1440/1080 = 1.3333`，16 设备像素 = **12 虚拟像素**，正好是多条色条拼接的接缝周期。

**真因**：压暗/暗角是用 `for (i…) Box(Rect)` 拼出来的（每条 4~5 px、半透明黑）。
`GUI.matrix` 是**非整数缩放**（1.3333），每条色条的边缘落在非整数设备像素上，
光栅化时相邻条要么露 1px 缝（露出底下较亮的照片 → 亮线）、要么重叠（alpha 叠加 → 暗线）。

**修法**：改成**一张渐变贴图 + 一次 DrawTexture**，让 GPU 双线性插值负责过渡，天然没有接缝：

```csharp
UiKit.FadeDown(rect, color);   // 顶部不透明 → 向下淡出
UiKit.FadeUp(rect, color);     // 底部不透明 → 向上淡出（UV 翻转）
UiKit.FadeRight / FadeLeft     // 左右同理
UiKit.Vignette(vw, strength)   // 四边暗角，内部就是这四个
```

贴图是 1×256 / 256×1 的白色渐变（`FadeV()` / `FadeH()`），运行时生成一次缓存，
染色靠 `GUI.color`。顺带把 draw call 从 220 次降到 **1 次**。

**顺带修掉的第二处**：封面那条"扫描光带"原来是 14 条 5px 半透明横条拼的，同一个毛病，
改成 `FadeUp + FadeDown` 两张贴图拼一条软光带。

**结论（写进肌肉记忆）**：
- 两端**同色只变透明度**的压暗/淡出 → 一律用 `FadeDown/FadeUp/FadeLeft/FadeRight`。
- `VGradient/HGradient` 只留给**两端颜色不同**的场合（如 `Backdrop` 的整屏底色），且它叠在照片上照样会出线。
- 判断依据：只要 `GUI.matrix` 有缩放，逐条拼的半透明矩形就**必然**在接缝处出错。

### 11.4 运行时怎么用

```csharp
// 封面（GameStartScreen）
static Texture2D _bg; static bool _bgTried;
static Texture2D Bg() {
    if (!_bgTried) { _bgTried = true; _bg = Resources.Load<Texture2D>("UiBackdrops/cover"); }
    return _bg;
}
UiKit.Alpha = 1f;                                    // 封面不参与淡入淡出，防别的界面残留污染
UiKit.PhotoBackdrop(vw, Bg(), 0.50f, 0.74f, 0.88f, 0.34f);

// 车库（GarageScreen）
UiKit.PhotoBackdrop(vw, Bg(), 0.62f, 0.58f, 0.88f, 0.40f);
```

- **没跑生成器也不会崩**：`PhotoBackdrop` 收到 null 会自动退回原来的纯渐变 `Backdrop()`。
- 静态缓存 `_bgTried` 是必须的，否则每帧 OnGUI 都会 `Resources.Load` 一次。

### 11.5 还能怎么改进

- 封面顶部天空占比偏大、偏空。想更满可以把机位压低一点（`y` 230 → 150）或 FOV 收到 40。
- 车库背景现在是"虚化城市剪影"，可以再压暗 0.05~0.1 让卡片更跳。
- 想要更强的"电影感"：给封面加一层极淡的**横向光晕**（暖色，沿地平线）或者把暗角从四边改成椭圆形。
