## 2. 这一轮到底修了什么

### 2.1 根因：一条被忽略的导入设置（最关键的发现）

`Assets/Models/Vehicles/Split/light_tracks3_clean.fbx` 的 `isReadable = 0`（没勾 Read/Write Enabled）。

后果是**整条履带链路静默失效**：

| 调用 | 结果 |
|---|---|
| `mesh.vertices` | 抛 `Not allowed to access vertices ... (isReadable is false)` |
| `CollectBelts()` | `BuildBelt` 抛异常 → **`_belts.Count == 0`**（运行时 dump 实测 `belts=0`） |
| `TrimRadial()` / `ShiftMesh()` | 抛异常 → 轮子不纠偏心、不截尖刺 |
| `RebuildEndWheels()` | 因为 `_belts.Count == 0` 直接 return |

**履带一条都没被接管**：不转、碎片不清理、端部轮不重建。画面上只表现为"履带有点怪"，很容易误判成美术问题。

对照：`light_tracks3.fbx` / `main_tracks3.fbx` / `heavy_tracks3.fbx` 都是 `isReadable = 1`，**只有 Blender 重新导出的这条中招**。

> 已修：`ModelImporter.isReadable = true` 重导，并在 `TrackAssembly.Start()` 加了 `CheckMeshesReadable()` 硬闸——不可读就 `LogError` 并停手，不再静默。

### 2.2 那条网格本身也救不回来

顶点到中心线的偏移是**连续分布**（单位米）：

| p50 | p75 | p90 | p97 | p99 |
|---|---|---|---|---|
| 0.11 | 0.22 | 0.34 | 0.50 | 0.56 |

**没有任何阈值能把"履带板"和"内侧那团碎面"分开**。打开读权限后，之前那 5 层启发式补丁的副作用立刻现形：

- **端部轮重建**判据是"轮子列表里 z 最外 8%"，但轻坦真正的主动轮在 `static_clean` 里、**不在列表里** → 把最前面两个**负重轮**换成了大圆盘；
- **按半径截断**用"中位半径 × 1.25"，而轮盘顶点往圆心密集分布，中位半径只有外径的 0.78 → 把 0.43 m 的负重轮切成 **0.35 m**；
- 履带环高 1.41 m、负重轮只有 0.88 m，顶上那段履带悬空 0.5 m，**没有托带轮撑着**。

### 2.3 改法：不再修烂网格，按尺寸生成

新增 `Assets/Scripts/Units/TrackAssembly.Procedural.cs`（`TrackAssembly` 改成 partial）：

```
stadium 环（两直段 + 两个半圆）
  ├─ 4 条面：外 / 右 / 内 / 左            每条面独立顶点，棱角是硬的
  ├─ 每 3 个环做一次"凸起"                → 侧影上一节一节的履带板
  ├─ 主动轮（前端，12 齿）+ 诱导轮（后端）
  ├─ 负重轮 ×N（轮缘台阶 + 凸出轮毂 + 5 根辐条 + 5 颗螺栓）
  └─ 托带轮 ×2（撑着上段履带，不再悬空）
```

- 顶点 UV2 直接按弧长写入 → 复用现有 `Tank/TrackBelt` GPU 顶点动画（`_PathArr` 255 点）；
- 轮子走原来那套自转逻辑（ω = v/R，差速转向照旧）；
- 材质：履带深钢色（0.20）、轮子稍浅（0.30）、辐条/螺栓用**浅色 Unlit**（0.62）。

### 2.4 轮子转动可见性（用户第二轮反馈）

用户原话："轮子转动的痕迹不明显，说人话就是有点看不出来，能不能加点纹路或者轮毂什么的"。

改法：每个轮子加 5 根辐条 + 5 颗螺栓，放进**第 2 个 submesh**，用 Unlit 材质靠颜色对比。5 是奇数，避免"转 72° 和没转一样"的对称感。

## 5. 这一轮踩的坑（别再踩）

| 坑 | 现象 | 修法 |
|---|---|---|
| **FBX 没勾 Read/Write Enabled** | `mesh.vertices` 抛异常，整条履带链路静默失效，`belts=0` | 导入设置勾上；代码里加 `CheckMeshesReadable()` 硬闸 |
| **`Mesh.SetTriangles(list, 1)` 不撑 subMeshCount** | Unity 6 里静默丢弃 → 第 1 槽永远空，辐条根本不渲染 | 先 `mesh.subMeshCount = 2` 再 SetTriangles |
| **双面四边形共用顶点** | `RecalculateNormals` 把两个绕向的法线平均成 0 → 纯黑 | 两个绕向各用一套顶点（`AddQuad2`） |
| **辐条和轮缘端盖共面** | z-fighting，辐条只剩一条头发丝 | 往外再凸 2 mm |
| **辐条凸太高 + 轮子开投影** | 轮面糊出一圈黑三角（自投影） | 凸起压到 6 mm，轮子 `ShadowCastingMode.Off` |
| **`GameStartScreen` 按住 timeScale = 0** | 截图台里车一动不动、6 帧一模一样 | 截图台里 `Destroy` 掉它 |
| **`Vector3` 插值格式串** | `{pos:F2}` 在部分版本上不支持 | 用 `pos.ToString("F2")` |
| **判据建立在"轮子列表"上** | 轻坦真正的主动轮在 `static_clean` 里、不在列表 → 换错轮子 | 不要再加这种"按列表最值猜"的启发式 |

## 7. 给下一个人

- **先看 `dump.txt`，再看图**。履带这类问题，运行时数据（`belts=?`、`gpu=?`、偏移分位）比截图快十倍。
- **Unity 读网格抛异常不会中断程序**，只会让那段逻辑静默失效。凡是读网格的代码，先 `if (!mesh.isReadable)` 吼一声。
- **别再在烂网格上加启发式补丁**。这一轮之前的 5 层补丁（TrimToXBand / p97 带宽 / 轮轴排除 / 压平碎片 / 端部轮重建）互相打架，每修一处带出新的一处。数据分布是连续的时候，"按阈值筛"注定失败 —— 该重建就重建。
- **验收一律走 `DevTankShots`**，别再用 `DevCapture` 挑角度自证。
- 用户对履带非常在意，已经否过四次。改完先自己跑截图台看，再交给用户。
