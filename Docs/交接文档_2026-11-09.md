## 2. 【重要】D3D12 原生崩溃 —— 根因与结论

**现象**：c~j 八个包启动后 40~100 秒内**原生崩溃**，没有 C# 异常，`Player.log` 里只有：
```
Crash!!!
... 0x... (nvwgf2umx) NVAPI_Thunk
... 0x... (D3D12Core) D3D12GetInterface
... 0x... (UnityPlayer) UnityMain
```
编辑器日志里另有明确信息：
```
d3d12: GfxDevice was not out of Non-Local memory
Budget: 7754467943   CurrentUsage: 1.4 GB
CurrentReservation: 4011451699   AvailableForReservation: 0
d3d12: Unrecoverable GPU device error!
```

**排查方法（以后照用）**：`Assets/Scripts/Dev/PropDebugToggle.cs` —— 按命令行参数关掉场景里的部分物件，
**一次打包测多种组合**，不用每换一个变量就重新构建：
```
Tank3D.exe -noprops        # 关掉整个 Props
Tank3D.exe -nobuildings    # 只关建筑
Tank3D.exe -notrees        # 只关树
Tank3D.exe -norocks        # 关岩石+灌木
Tank3D.exe -nocolliders    # 保留模型但禁用碰撞体
Tank3D.exe -noshadow       # 全部关阴影
```
（不带参数启动时它什么都不做，可以留在正式版里。）

**二分结果**：

| 测试 | 结果 |
|---|---|
| `-noprops` | 稳定 165 s |
| `-nobuildings`（留树） | 崩 |
| `-notrees`（留建筑/石/灌木） | **稳定 95 s** |
| `-nocolliders` | 崩（跟碰撞体无关） |
| `-noshadow` | 崩（跟阴影无关） |

**结论**：**树是唯一元凶**，而且不是面数、不是碰撞、不是阴影 —— 是**我用 Blender 重新导出过的树网格**。

具体两处手改：
1. `fix_tree_base.py`：删掉树根土台面（4 棵树）
2. `decimate_props.py`：所有模型 decimate 到 1/6 面数

这两个脚本导出的网格，Blender 侧检查完全干净（无 NaN 顶点/法线/UV、无零面积面），
但 D3D12 的 NVIDIA 驱动路径渲染它就会挂；**同样的模型走 D3D11 完全正常**（`-force-d3d11` 验证过）。

**修法**：6 棵树全部退回 `ArtSource\Props_original\` 的原始 Lux3D 导出（一个顶点都不手改），
土台改用"下沉 13%"解决。建筑保留 decimate（6000 面，建筑不崩）。

**⚠️ 教训**：Lux3D 出的 fbx **不要手工删面/decimate 后再用**，尤其是带 custom split normals 的网格。
要调外观优先用「变换」（缩放/下沉/旋转），不要动几何。

### 3.2 炮管打不出来（用户报"炮管修好了实际仍然打不出来"）
- 根因：`Player.log` 里 `[Module] 炮艇 的 Gun 被打坏` 出现 3 次 —— 部位伤害系统把炮管打坏后 `gunBroken = true`，
  而 `CanFire` 要求 `!gunBroken`，且**没有自动修复**，只能去 TAB 商店买修复
- 修法（`VehicleModule.cs` / `MatchHUD.cs`）：
  - 炮管耐久 ×3（`gunDurabilityMul`）
  - 打坏后 **15 秒自动修复**（`gunRepairSeconds`，修好后半条命）
  - HUD 炮管格显示「修理中 Xs」，准星下方加红字提示
  - 炮管判定盒改成按**炮塔→炮口的真实长度**算（原来炮艇算出来在船头前方 8.7 m）
  - 商店买模块修复时同步清 `gunBroken`

### 3.3 树/建筑穿模（用户报"所有的树和建筑物都会穿模"）
- 撒点重写（`PropScatter.cs`）：
  - **空间哈希占位去重**：每个物件按模型真实包围盒算占地半径，建筑 ×1.04、树 ×0.55、岩石 ×0.7、灌木 ×0.8，共用一张表
  - 建筑从"等距网格"改成"城区内随机撒 + 互斥"，网格尺寸和楼体尺寸不再打架
  - `Place()` 减去模型自身最低点做**底面贴地**
  - 修了一个隐蔽轴向 bug：Lux3D 的 fbx 根节点带 270° X 旋转，原来 `rotation = Euler(0,yaw,0)` 把它覆盖掉 → 所有模型躺地上

## 4. 今天踩的坑（血泪）

1. **Lux3D 的 fbx 不要手改几何**（见 §2）—— 这是今天最大的坑，烧了 8 个包。
2. **Unity 许可客户端会坏**：反复强杀 Unity 进程后出现
   `[Licensing::Client] Code 10 while verifying Licensing Client signature` → `Licensing initialization failed`，
   编辑器**完全起不来**（GUI / batchmode / 重开 Hub 都不行，exe 签名有效、ACL 干净）。
   **只有重启电脑能恢复。** 别指望杀进程能修。
3. **`-batchmode` 必须带 `-quit`**：不带的话 `-executeMethod` 跑完进程不退出，一直占着项目锁，
   下次启动报 "another Unity instance is running with this project open"。
4. **管理员权限的 Unity 进程，普通权限杀不掉**（Access denied）。要用提权 PowerShell 或任务管理器。
5. **`Physics.ComputePenetration` 不要用在载具挤出上** —— 实测直接原生崩溃。
6. **手改 `.meta` 文件（贴图 maxTextureSize）**：能生效，但后来怀疑是崩溃因素时又全删了重生成。
   要改导入设置优先用 `TextureImporter` API，不要文本替换。
7. **对照实验要用旧包**：每次怀疑"是不是我改坏了"，先跑上一个已知可用的包，能立刻区分"环境问题"和"改动问题"。

### 6.1 城区扩大（2026-11-09 下午，用户要求"减少中间平原、扩大城区、多加几个建筑"）

改了三处：
- `BattlefieldTerrainBuilder.HeightDesign` / `CityMask`：城区 z 从 `0~14` 扩到 **`−14~17`**（深度 ×3），
  把山脚和城区之间那条大平原吃掉

`OneShotRebuild.RunTerrain()` 是安全版本（逐块 BuildTile → Invalidate → Scatter → 打包）。
