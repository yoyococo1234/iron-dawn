> 用户给的参考图：机位在机尾后上方俯看机背，地平线落在画面上方 1/5 左右，
> 地面占满大半屏，飞机在画面中下方 —— 这样不开镜也能对地瞄准。
> 顺带把「开镜」做出来（以前飞机按右键/Shift 完全没反应）。

工程 `D:\UnityProjects\Tank3D`　场景 `Assets/Scenes/Map_Battlefield.unity`

---

## 1. 改了什么

### 1.1 `Scripts/CameraFollow.cs` — 飞机追尾机位重做

原来是「贴着机尾、视线基本水平」：机位只在机身上方 `0.22×距离`，视线沿机头打 80 m 外一个点。
结果地平线卡在画面正中间，上半屏全是空天，飞机正好压住屏幕中心。

新增四个可调参数（`CameraFollow` 的 Inspector 里，飞机追尾那一栏）：

| 参数 | 值 | 含义 |
|---|---|---|
| `airDistanceFactor` | **0.64** | 跟机距离 = 按机身体积算出的距离 × 该值 |
| `airHeightFactor` | **0.52** | 机位抬高量 = 跟机距离 × 该值（≈ 从斜上方俯看机背） |
| `airLookDownDeg` | **18** | 视线相对水平压低多少度 |
| `airZoomFov` / `airZoomDistFactor` | **22 / 2.2** | 开镜收窄到的视野角 / 开镜时机位退远的倍数 |

三个关键实现细节：

1. **机位用「水平机头方向」而不是机头本身**。
   机头抬头/俯冲时，如果用 `target.forward` 算机位，镜头会跟着甩到机背上方或机身下方，
   画面构图一直变。改成把机头投影到地面再取方向，构图就稳定了。
2. **压低角度按世界水平算，不按机头算**。
   这样地平线在画面里的高度是固定的：视野 50° 时压 18° ≈ 地平线在画面上方 22%。
   按机头算的话，飞机一爬升地平线就往下跑（实测爬升 5° 时地平线从 23% 掉到 31%）。
3. **开镜时把机位退远，而不是拉近**。
   视野从 50° 收到 22° 是放大 2.3 倍，如果机位不动，一开镜满屏都是机背。
   `airZoomDistFactor = 2.2` 让飞机在画面里大小基本不变，被放大的是地面 —— 这才是「开镜」。

### 1.2 `Scripts/Match/MatchHUD.cs` — 空战开镜分划

- 新增 `IsAirScoped()` + `DrawAirScope()`：细圆环 + 四向刻线 + 内圈四点 + 中心红点 + `×2.3` 倍率提示
- **不画坦克那圈黑色镜筒**：那是炮镜，飞机上套一圈黑边很怪
- `DrawCrosshair` 里，飞机开镜时改画这套分划，不画原来的小黄圈

### 1.3 换车时的状态残留

`CameraFollow` 的 `_scoped` / `_rightZoom` 是坦克那套的状态。从坦克（开着镜）换到飞机时，
飞机分支原来直接 `return`，这两个值会留着，结果飞机上套着一圈黑色炮镜。
现在飞机分支开头把它们清掉，并且飞机用独立的 `AirScoped`。

编辑器 Play 模式 → `MatchManager.DeployPlayer(战斗机)` → `ScreenCapture.CaptureScreenshot` 落盘 → 读图比对。

| 版本 | 地平线 | 飞机中心 | 结论 |

## 3. 没做的 / 可能还要调的

- **灵敏度**：飞机开镜后没有像坦克那样乘 `zoomSensitivity`（0.3）。
  飞机开镜时鼠标是操控飞机的，不是转镜头，所以暂时没动 —— 如果觉得开镜后太灵敏，
  在 `VehiclePhysics.UpdateAir` 里按 `CameraFollow.AirScoped` 乘个系数即可。
- **镜头随俯冲**：现在视线压低量是相对**世界水平**的，所以俯冲时镜头不会跟着往下压。
  想要"俯冲时看得更往下"，得在 `ChaseCamera` 里把 `airLookDownDeg` 和机头俯角混一下。
- 参考图里那台是攻击机（双发、翼展更宽），这次的截图用的是战斗机，两者在画面里的占比会差一点。

# 第二轮（同日 10:30）：抬头时"飞机横满屏幕"的怪画面

用户截图：飞机抬头时镜头还在往下看地面，飞机被从上方俯视、机身横满屏幕。

## 5. 两个根因

### 5.1 镜头没跟着飞机姿态（主因）

第一版为了"构图稳定"，机位用的是**机头的水平投影**、视线压低量按**世界水平**算。
结果是：飞机抬头 35°，镜头照样水平看地面 —— 于是变成"从上面俯视一架正在爬升的飞机"。

战雷（看了 B 站 WT 二战螺旋桨空战视频抽帧）是**镜头跟随机身姿态**的：
抬头就看天、俯冲就看地、压杆地平线跟着倾斜。这才是"在开飞机"而不是"在看飞机"。

改成：
- 机位 `planePos - forward*dist + up*dist*heightFactor`（forward/up 都取飞机自己的）
- 视线 `planeRot * (AngleAxis(airLookDownDeg, Vector3.right) * forward)` —— 压低量在**飞机坐标系**里
- `airRollFollow = 0.85`：镜头 up 向飞机 up 插值，压杆时地平线跟着斜

### 5.2 跟机距离太近（次因）

原来 10.2 m。飞机 11 m 长，平飞时只看到机尾（透视缩短），看着还行；
一旦抬头，机身横过来，10 m 距离下**直接横满屏幕**。

战雷的飞机在画面里只占 15~20%。现在改成：

| 参数 | 值 |
|---|---|
| `airDistanceFactor` | **1.0** |
| `airMinDistance` | **17 m**（硬下限，滚轮拉到底也不会更近） |
| `airMaxDistance` | 44 m |
| `airHeightFactor` | **0.5** |

实测平飞 ~27% 画宽，抬头 35° ~35% 画宽 —— 不会再出现横满屏幕。

## 6. 验证方法（踩过的坑）

`ScreenCapture.CaptureScreenshot` 在 **script-execute 的同一次调用里**截图，截到的是**改动之前**那一帧
（`LateUpdate` 还没跑）—— 我因此误判了两轮。正确做法：改完 → 等 3~4 秒 → **另起一次调用**再截。

另外 `airRoll` / `airPitch` 这类字段每帧会被 `UpdateAir` 重算，直接赋值会被覆盖；
要测姿态就 `pl.Physics.enabled = false` 再直接改 `transform.rotation`。

# 第三轮（同日 11:15）：准星改成"机头指向"

用户：屏幕中间那个十字永远在中间，不知道是干什么的；既然开镜时知道炮口在哪，准星也应该瞄着要打的位置。

## 8. 问题

镜头压低 18° 俯看机背之后，**屏幕中心 ≠ 机头指向**。而 `GetAimPoint()` 原来是拿
屏幕中心射线算瞄准点的，等于子弹打向"画面中心那个点"，和机头指哪完全脱节 ——
准星就成了一个没有意义的装饰。

## 9. 改法：两边一起改，不然还是对不上

| 改哪 | 原来 | 现在 |
|---|---|---|
| 准星画在哪（`MatchHUD.DrawCrosshair`） | 屏幕中心 + AirAim 偏移 | **机头方向的屏幕投影**（`WorldToScreenPoint(pos + forward*900)`），并夹在画面内 |
| 子弹往哪打（`PlayerTankController.GetAimPoint`） | 从相机沿屏幕中心射线 | **从机身沿机头方向射线**，命中点当瞄准点 |
| 开镜时的镜头（`CameraFollow`） | 照样压低 18° | `airScopeLookDownDeg = 0`，正对机头 |

第三行是必须的：开镜视野只有 22°，压低 18° 的话机头准星直接飞出画面。

## 10. 结果

- **不开镜**：准星落在机头指向的地方 —— 平飞时就在天边（和地平线重合，因为机头指哪打哪），
  俯冲时跟着压到地面。
- **开镜**：视野 22°、正对机头，准星分划在画面正中，飞机在视野外 —— 就是机炮瞄准具。
- 辅助瞄准（导弹 20° / 机炮 6° 锥角）现在也是以**机头方向**为轴，不再是屏幕中心。

# 第五轮（同日 12:00）：坦克/炮艇的镜头也按飞机那套抬高

用户：把镜头稍微往上抬一抬，按修飞机那个方法修。

## 15. 原来坦克镜头的问题

```csharp
transform.rotation = Quaternion.LookRotation(pivot - transform.position);  // 盯着车看
```

镜头是"绕车转、盯着车"的，车身永远在画面正中。炮口准星虽然改对了方向，但离车身只有 ~10° 夹角
（炮管水平、镜头俯视 8°），准星几乎贴在炮塔上，远处不好瞄。

## 16. 改法：和飞机一模一样的三件套

| 项 | 原来 | 现在 |
|---|---|---|
| 机位 | `pivot - Euler(pitch,yaw)*forward*dist`（跟着俯仰绕） | `pivot - flat(yaw)*dist + up*(dist*tankHeightFactor)`，**只跟水平朝向** |
| 视线 | 看向车身（`pivot - position`） | `Euler(tankLookDownDeg + (pitch-8), yaw)` —— 固定压低 |
| 新增参数 | — | `tankHeightFactor = 0.32`、`tankLookDownDeg = 10` |

效果：车身落到画面下方 2/3、炮口准星升到中上部，两者拉开约 30% 屏高。
鼠标俯仰仍然有效（`pitch` 默认 8° 当水平，往上推就减小压低量，能抬头打飞机）。

# 第六轮（同日 12:35）：开镜时视野要跟着炮塔转

用户：准星应该是**炮塔真正朝向的位置**。视角转过去了、炮塔还没转过来，它得转 ——
准星要跟着炮塔走；不能是"我转过来准星就过来了，炮塔没跟"。

## 18. 病根：开镜分支的视线还是鼠标方向

不开镜的准星上一轮已经改成炮口投影（会滞后）。但**开镜分支**里写的是：

```csharp
Vector3 lookDir = Quaternion.Euler(pitch, yaw, 0f) * Vector3.forward;   // 鼠标方向
```

镜头跟着鼠标瞬间转，炮塔按 `turretTurnSpeed`（主战 80°/s）慢慢追 ——
开镜时准星在屏幕正中，就变成"准星先到、炮塔后到"。

## 19. 改法：视线直接取炮口朝向

```csharp
Vector3 lookDir = vp != null && vp.muzzleBone != null
    ? vp.GetMuzzleForward()
    : Quaternion.Euler(pitch, yaw, 0f) * Vector3.forward;
```

原来的注释说"跟炮管会形成 相机→炮塔→相机 的反馈、放大后炮塔会自己漂"。**其实不会**：
炮塔的目标角来自 `camFollow.yaw`（只由鼠标驱动），相机只是**读**炮口、不回写，没有闭环。
（旧代码怕是当年 `AimTurretAt(相机射线命中点)` 那条路留下的印象 —— 那条路才是闭环。）

实测：`camFwd` 与 `muzzleFwd` 夹角 **0.00°**；把鼠标 yaw 猛拉 +50° 后，
`camYaw=140` 而 `turretYaw=72.4`（炮塔还在追），相机与炮口夹角仍只有 **0.15°** ——
即视野是跟着炮塔转过去的。

# 第八轮（同日 13:10）：开镜后瞄准自己漂、鼠标推不动

用户：开镜的时候无法控制瞄准位置，它会自己动。

## 25. 根因：我上一轮埋了一个**闭环**

上一轮为了让"炮口正好指向准星"，把炮管俯仰改成读**相机的实际俯仰**：

```csharp
float wantPitch = -Mathf.DeltaAngle(0f, _cam.transform.eulerAngles.x);   // ❌ 闭环
```

但**开镜时相机是跟着炮口走的**（第六轮改的 `lookDir = GetMuzzleForward()`）。于是：

```
炮口俯仰 → 相机俯仰 → 炮管目标俯仰 → 炮口俯仰 → ……
```

闭环 = 瞄准自己漂、鼠标推不动。这正是第七轮文档里我自己写下"相机只是读、不回写"的地方，
结果反手又让炮管去读相机。

## 26. 改法：炮管只认鼠标

```csharp
float wantPitch = -(camFollow.tankLookDownDeg + (camFollow.pitch - 8f));   // ✅ 只依赖鼠标
```

`camFollow.pitch` 只由鼠标改，相机只是**读**炮口 —— 环断开了。

顺带修了一个 2° 的偏差：开镜分支的看点是 `camPos + lookDir*300`，而 `camPos` 在算完之后
还会被"地面/自身碰撞盒抬高"修正，导致视线比炮口歪约 2°。改成从**实际相机位置**推出去。

## 27. 实测

| 场景 | 结果 |
|---|---|
| 开镜静止 3 秒 | `pitch=8.0 barrelPitch=-7.9 camPitch=10.0` —— **不漂** |
| 模拟鼠标上推（pitch 8→2） | `barrelPitch -7.9 → -1.9`，相机跟着到 `camPitch 4.1` —— **能控** |

# 第九轮（同日 13:20）：开镜时"炮塔自己往一边转" —— 视差环

用户自己把病根说对了：**开镜时准星就是炮口**，但代码里还有**另一个看不见的瞄准点**，
炮塔追着那个看不见的点转，所以"准星在这儿、炮塔往别处去"。

## 29. 那个"看不见的准星"是相机射线

`PlayerTankController.Update` 里每帧都做：

```csharp
aimPoint = GetAimPoint();                     // ← 相机中心射线打到的点
_combat.Physics.AimTurretAt(aimPoint, turn0); // ← 炮塔朝它转
```

不开镜时没问题（相机在车后、中心射线大致就是准星方向）。但**开镜时相机挂在炮塔后方 2~3.6 m**，
还跟着炮口走。于是"相机中心射线"和"炮口方向"差了一个**视差**：

```
炮口 → 相机（后退 3 m）→ 中心射线打到的点偏一边 → 炮塔朝它转 → 相机跟着转 → 视差又变 → …
```

打近处物体时视差能有好几度，于是炮塔就一直往一边拧 —— 就是"不停使唤"。

## 30. 改法：开镜时彻底不用相机

1. **开镜时不调用 `AimTurretAt`** —— 瞄准完全交给 `AimDirect`（只认鼠标的 yaw/pitch）。
2. **开镜时 `GetAimPoint` 直接沿炮口推出去**（`GetMuzzlePosition + GetMuzzleForward*4m` 起算），
   和相机位置无关。

这样开镜链路里相机**只读不写**，没有环。
