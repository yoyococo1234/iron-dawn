## 4. 已知问题 / 下次要先验证的

1. **地形外观**：上一版实景里，山体有横向"褶皱"感（LOD 台阶）+ 分块黑裂缝。已做的修复：分块邻居索引 bug 修正、`heightmapPixelError` 3→1.5、山体噪声加中/高频脊、路面压噪。**但都是改完代码没重建，未验证。**
2. **山坡陡峭比例**：v1 版山地象限有 63% 面积 >30°（只有轻坦能上）。v2 的山脚过渡已放宽到 22 设计 m，预计改善，需重跑后实测。
3. **资源点数量变了**（4→5），占领/产金逻辑一个都没写。
4. **出兵线 z 到 ±58**：v2 里 z>20 是海，出兵线两端（z 20~58）在海里，陆军不能在那里出生——需要在实现出兵时按 z 限制到陆地，或者改出兵线范围。

Unity 菜单：`Tools → 铁皮黎明 → ① 生成正式战场地形（2000×2000）`

或者用 MCP 分块跑（每次一块约 75~115 秒，避免调用超时）：

```csharp
// MCP script-execute 逐块调用
BattlefieldTerrainBuilder.BuildTile(0);   // 左下
BattlefieldTerrainBuilder.BuildTile(1);   // 右下
BattlefieldTerrainBuilder.BuildTile(2);   // 左上
BattlefieldTerrainBuilder.BuildTile(3);   // 右上
BattlefieldTerrainBuilder.FinishScene();
```

⚠ **调用前必须先单独 import 一次**，否则跑的是旧程序集（本次踩过，白等 6 分钟）：

```csharp
AssetDatabase.ImportAsset("Assets/Editor/BattlefieldTerrainBuilder.cs", ImportAssetOptions.ForceUpdate);
```

## 7. 本次踩的坑（新增）

| 坑 | 现象 | 修法 |
|---|---|---|
| **新代码没编译就调用** | 改了 `.cs` 立刻在同一个 MCP 调用里跑生成，结果跑的是旧程序集，白等 6 分钟 | `ImportAsset` 单独一次调用，等编译完再跑业务调用 |
| **分块地形 SetNeighbors 索引算错** | `RoundToInt(pos.x / TileSize)`，tile 原点是 −1000/0，算出来 −1/0，等于没设邻居 → 地形出现黑色裂缝 | 加上 `+ MapSize*0.5` 再除 |
| **混合图采样按整图算** | 分块后 `SampleWorldY` 还用整张 2000 m 换算索引，左半张图采样到别处，判成 98% 岩石（看着像"接缝"） | 传块原点 `ox/oz`，按 `TileSize` 换算 |
| **鞍部和公路叠加抬升** | 先削公路再压鞍部，两段抬升叠加，公路纵坡从 14° 涨到 28.9° | **先鞍部、后公路** |
| **公路被细节噪声顶坑洼** | 世界尺度 3 m 噪声加在路基上，纵坡超标 | 用 `PassRoadMask` 把公路上的噪声压掉 90% |
| **`?? ` 判空对 Unity 对象失效** | `GetComponent<Camera>() ?? AddComponent<Camera>()` 抛 MissingComponentException | Unity 的伪 null 不吃 `??`，要写 `if (x == null) x = ...` |
| **terrain 数据入库太大** | 4 块 4097 地形 ≈ 303 MB | 加进 `.gitignore`，靠菜单重生成 |

## 8. 下一步建议（给自己）

1. 先重建 + 截图验证外观（褶皱问题是否解决）。
2. 若山体仍显"墙"，优先调 `MountainField` 的 `ramp`（z −18~−40）和 `massif` 参数——用预览器秒出，别每次重建。
3. 外观 OK 后再动数据层和载具适配。
