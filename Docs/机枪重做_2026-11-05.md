## 1. 模型（`Assets/Scripts/Units/VehicleModelBinder.cs` → `BuildDeckGun`）

### 层级

```
DeckGun            底座，贴塔顶，不俯仰
└── MG_Yoke        耳轴，绕 X 俯仰（= vp.mgBone）
    ├── 摇架两块侧板 / 机匣 / 机匣顶盖 / 尾板
    ├── 散热套筒 + 3 圈散热环
    ├── 枪管 + 消焰器
    ├── 弹箱 + 输弹口（左侧）
    ├── 双手握把（短粗，贴机匣尾部往下翘）
    ├── 环形照门（16 段小方块拼环）+ 前准星
    └── MG_MuzzlePoint   出膛点（vp.mgMuzzle）
```

**为什么要分两层**：旧版把整个挂点当转轴，一抬枪整根立柱跟着"翻下去"。
现在 `mgBone` 指摇架，绕耳轴转 —— 底座和立柱不动，枪身抬头，这才是枪架的动作。

### 无缝隙的关键（踩过的坑）

第一版用「5 个采样点里的**最高点**」当底座高度 → 塔顶是斜的，底座低的一侧**悬空**（截图 `mg_b_side.png` 就是）。

改成 `MeasureRoofY()`：临时给塔体网格挂 MeshCollider，从正上方打 **9 个点**（中心 + 半径 0.26 一圈），
取**最低点**坐下，再夹一个「最多比最高点低 10 cm」的保险（塔顶有大台阶时不至于整挺机枪陷进去）。
底座圆盘 0.54 m、压进塔面 2 cm —— 上坡侧沉进塔体（看不见），下坡侧贴住。

> 这套做法和「炮塔井补板」是同一个套路：临时 MeshCollider → 射线实测 → 删掉。

### 顺带修的显示问题

机枪零件原本被 `VehicleCombat.ApplyTeamTint` 的阵营色调染成浅蓝白 ——
`MaterialPropertyBlock` 是**替换** `_Color` 不是相乘，黑铁直接被洗白。
现在 `ApplyTeamTint` 跳过名字以 `MG_` 开头的渲染器，机枪保持枪械本色。

## 2. 机枪独立模式（`PlayerTankController` / `VehicleCombat`）

| 项 | 行为 |
|---|---|
| `V` | 进/出机枪模式（只有装了 deckMounted 武器的载具有效） |
| `Q` | **只在炮塔武器之间循环**（炮艇：舰炮 ⇄ 鱼雷）。`CycleWeapon()` 里 `if (w.deckMounted) continue;` |
| 左键/空格 | 机枪模式下打机枪（`FireDeckGunAt`），否则打当前炮塔武器 |
| 瞄准 | 机枪挂在炮塔上 → 偏航仍由 `AimDirect` 把炮塔转过来；**俯仰**走机枪自己的限位（+85° / −12°，150°/s） |

`VehicleCombat` 新增：

- `DeckWeapon` —— 第一把 `deckMounted` 武器
- `FireDeckGunAt(aimPoint)` —— 独立装填计时 `_nextMgFireTime`，和 `weaponIndex` 无关
- `CycleWeapon()` 跳过机枪

开火方向**不给瞄准点**（传 null），直接用 `GetDeckGunForward()`：
准星画的就是枪管指向，不存在"准星和弹道对不上"。

## 3. 机枪瞄准镜（`CameraFollow` + `MatchHUD`）

思路照抄飞机开镜：**镜头贴在枪口后方、正对枪管**，视野收到 `mgScopeFov = 26°`。

| 参数（CameraFollow） | 值 | 含义 |
|---|---|---|
| `mgScopeFov` | 26 | 开镜视野（飞机是 22，机枪给宽一点，方便扫射） |
| `mgScopeBack` | 1.15 | 机位在枪口后方多远 |
| `mgScopeUp` | 0.30 | 机位比枪口高多少 |
| `forceMgScopeForTest` | false | 截图/验收用，强制开镜 |

- `MgScoped` 为真时走独立分支：`camPos = muzzle - forward*back + up*up`，
  看点从**实际机位**沿枪管推出去（和炮镜同一个坑：用抬升前的机位会歪 2°）。
- 机枪模式下 `_scoped` 被强制 false，炮塔那圈黑色炮镜不会盖上来。
- 开镜时鼠标灵敏度乘 `zoomSensitivity`（0.3），不然 26° 视野里鼠标飞快。
- `MatchHUD`：`DrawMgReticle()` —— 不开镜画枪管指向的屏幕投影（出画面贴边），
  开镜画 `DrawMgScope()`：细圆环 + 四向刻线 + 密位刻度 + 中心红点 + `机枪 ×1.9` 提示。

# 第二轮（同日 10:40）：视角手感三条修正

用户反馈：① 移动鼠标视角转换很不自然；② 用炮时视角不能无限往上看（炮也抬不了那么高）；
③ 机枪可以抬高，开镜/不开镜都要分清。

## 6. 三个根因

| 现象 | 根因 | 改法 |
|---|---|---|
| 用炮还能往天上飘 | 相机 `pitch` 只有一对全局限位（`minPitch=-20`），和武器无关：炮艇炮管最多 12°，镜头却能抬 21° | 抬头上限改成**跟着当前武器走**（见下） |
| 机枪抬不到 85° | 同一对全局限位把机枪也卡在 21° | 机枪模式把下限放宽到 `-mgMaxElevation` |
| 视角转换不自然 | ① 机枪挂在炮塔上，炮塔只有 50°/s，鼠标一动画面明显跟不上；② 机枪镜的机位锚在**枪口**上，一抬枪镜头跟着往前上方平移，整个画面在"滑" | ① 给枪架加**独立回转座** `MG_Yaw`（200°/s），炮塔不动；② 机位锚到**炮塔坐标系**（摇架位置 + 炮塔水平前向），抬枪只转视线不挪机位 |

## 7. 抬头上限的算法

`pitch` 的语义：越大越往下看；镜头压低量 = `tankLookDownDeg + (pitch - 8)`。

```csharp
float upLimitDeg = mgMode ? vp.mgMaxElevation : vp.maxElevation;   // 85 / 12
float pitchFloor = 8f - tankLookDownDeg - upLimitDeg;              // 反解出 pitch
float pitchLo = mgMode ? Mathf.Min(minPitch, pitchFloor)           // 机枪：放宽
                       : Mathf.Max(minPitch, pitchFloor);          // 用炮：收紧
pitch = Mathf.Clamp(pitch, pitchLo, maxPitch);
```

这段在**鼠标输入处**，所以开镜 / 不开镜都吃同一套限位。

实测（炮艇）：

| 状态 | 强行把 pitch 设成 -70 | 结果 |
|---|---|---|
| 用炮 | 被夹到 **-11**（= 炮管 12° 仰角），炮管正好 +12 | ✅ |
| 机枪 | 保持 **-70**，机枪 `mgPitch=71`、`mgYaw=39.9`，炮塔 `turretYaw=0`（没被拖着转） | ✅ |
| 机枪开镜 | `pitch=-70` 时视野能抬到天上，机位相对摇架的偏移 `(-1.144, 0.289, -0.009)`，换成 `pitch=+71` 后是 `(-1.149, 0.296, -0.012)` —— **几乎不变 = 抬枪时镜头不平移** | ✅ |

## 8. 新增/改动

- `VehiclePhysics`：`mgYawBone` / `mgYaw` / `SetDeckGunYaw()`

# 第三轮（同日 10:55）：机枪回转限位 + 载具撞击"扣血后弹开"

## 10. 机枪限位

`VehiclePhysics.mgYawLimit = 120f`，在 `SetDeckGunYaw()` 里夹一次：

```csharp
deg = Mathf.Repeat(deg + 180f, 360f) - 180f;      // 折到 -180..180
deg = Mathf.Clamp(deg, -mgYawLimit, mgYawLimit);  // ±120°
```

实测：硬甩 +170° → 停在 **+120.0°**；甩 −170° → 停在 **−120.0°**。

## 11. 撞击为什么"卡在里面掉一大截血"

`VehicleCollision` 旧版每 0.08 s 做三件事：推开 0.12 m → 算相对速度 → 双方各扣一次血。
问题全在第一条：**两条 18 m 的船叠在一起，每 tick 只推 0.12 m，几秒钟都推不开**，
于是每个 tick 都判定一次撞击 —— 12.5 次/秒 × 每次上限 6% 血量，几秒就能掉掉小半管。
而且两边各跑一次 `Update`，一次接触被推两次、扣两次血。

改法（`VehicleCollision.cs` 重写）：

| 项 | 旧 | 新 |
|---|---|---|
| 顶开距离 | 固定 0.12 m/tick | **按真实重叠深度**（碰撞盒在法线上的半径之和 − 中心距），每次最多 1.6 m |
| 伤害频率 | 每 tick 都扣 | `damageCooldown = 1.2 s` 冷却 |
| 双方重复处理 | 两边各跑一遍 | 一对船只让 `InstanceID` 小的那边处理 |
| 撞完 | 只位移一点 | `VehiclePhysics.ApplyKnockback()` 给**反向冲量**（按相对速度，上限 9 m/s），前进速度压到 35% |
| 冲量落地 | — | `VehiclePhysics.LateUpdate` 里叠加位移并按 20 m/s² 衰减（载具不是刚体，没有横向速度，只能单独存一个矢量） |

实测（把一条 AI 炮艇硬塞进玩家船体，初始中心距 4.00 m）：

```
t0      距离 4.00 m   玩家HP 1368
t+120ms 距离 7.85 m   玩家HP 1355（扣了一次）  玩家 knockback 7.8 m/s
t+620ms 距离 16.40 m  玩家HP 1355（没再掉）    对方HP 796→778（也是扣一次）
```

120 ms 内被顶开 3.85 m 并带着 7.8 m/s 的冲量弹走，之后不再掉血 —— 就是"扣血 → 弹开"。

# 第十二轮（同日 16:25）：穿透系统（坦克世界那套，三处改良）

## 43. 公式

```
入射角   = 命中面法线 与 弹道反向 的夹角（0 = 垂直命中）
有效厚度 = 基础厚度 / max(0.2, cos(入射角))
穿深     = 弹药穿深 − 每 100m 衰减 × 距离/100   （化学能弹不衰减）
击穿     = 穿深 ≥ 有效厚度
入射角 > 70° 且没击穿 → 跳弹（0 伤害）
未击穿   → 伤害 ×10%（高爆弹 ×35%），且**不伤内部模块**（只能崩坏履带）
```

比 WoT 改良的三处：
1. **入射角用物理命中面法线算**，不用装甲板数据库 —— 零额外数据，斜着打真的会变厚。
2. **伤害浮动 ±10%**（WoT 是 ±25%，太看运气）。
3. **未击穿只伤外部件**，和已有的部位系统自洽。

# 第十三轮（同日 16:45）：三个 bug —— 多余履带 / 闪烁刺眼 / 命中听不见

## 48. 每台坦克多出一套履带（我的锅）

**根因**：出生保护的闪烁恢复时 `SetRenderersVisible(true)` 把**所有**渲染器都打开了，
包括 `TrackAssembly` 程序化履带故意隐藏掉的原模型履带（`hideSourceTracks`）。
表现就是"本来有履带，又多出一套奇怪的履带"。

**修法**：闪烁前记录每台渲染器原本的 `enabled`，恢复时**只恢复原本可见的**。

实测：主战坦克 81 个渲染器，闪烁结束后 61 个可见（20 个保持隐藏 = 原模型履带），
截图 `work\shots\tank_fixed.png` 只剩一套履带。

## 49. 闪烁太刺眼

# 第十六轮（同日 17:20）：鼠标视角手感（参考战争雷霆 / 坦克世界）

## 60. 查到的资料

- 战争雷霆 `controls.blk` 里的参数：[`cameraSmooth` / `cameraSpeed` / `mouseAimSens` / `gunnerViewSens` / `gunnerViewZoomSens`](https://forum-com.warthunder.ru/t/mouse-sensitivity-issues/88719/3)。
  玩家还反馈"鼠标移得太快会被减速" —— 说明它做了**输入加速度曲线**。
- 坦克世界设置里除了灵敏度，还有[「狙击模式水平稳定」](https://wiki.lesta.ru/index.php?title=%D0%9C%D0%B8%D1%80_%D1%82%D0%B0%D0%BD%D0%BA%D0%BE%D0%B2:%D0%9D%D0%B0%D1%81%D1%82%D1%80%D0%BE%D0%B9%D0%BA%D0%B0_%D0%B8%D0%B3%D1%80%D1%8B&curid=31211&diff=0&oldid=73478)
  这类独立开关，X/Y 灵敏度也是分开的。

**核心结论**：`cameraSmooth` 平滑的是**输入**，不是"让镜头追着输入跑"。

## 61. 我们原来的毛病（两处叠加）

```csharp
transform.position = Vector3.Lerp(pos, desired, followLerp * dt);   // 10/s，跟着鼠标转
transform.rotation = Quaternion.Slerp(rot, want, 14f * dt);         // 14/s，又慢半拍
```

鼠标一转，**机位和朝向各有一层滞后** → 整个画面被"拖着走"两拍。这就是"不自然"的来源。

而且两处都是 `k * dt` 形式的 Lerp —— **帧率相关**：30 FPS 每帧插 0.33，144 FPS 每帧插 0.07，手感完全不一样。

## 62. 改法

| 项 | 改前 | 改后 |
|---|---|---|
| 鼠标输入 | 原始 delta 直接加到 yaw/pitch | **指数平滑**（τ = 0.02 + mouseSmoothing×0.13），即战争雷霆的 cameraSmooth |
| 机位 | 跟着鼠标 Lerp（滞后） | **直接放**；只对**车体位移**做平滑（pivotSmoothTime = 0.06 s） |
| 朝向 | Slerp 14/s（慢半拍） | **直接 LookRotation** |
| 插值公式 | `k * dt`（帧率相关） | `1 - e^(-dt/τ)`（帧率无关） |
| X/Y 灵敏度 | 共用一个 | 拆成 `sensX` / `sensY` |

实测：鼠标 yaw 瞬间 +40°，**一帧内相机就转了 40.0°**（改前会明显滞后），0.3 秒后仍是 40.0°（不过冲）。

## 63. 可调参数（CameraFollow 面板）

| 参数 | 默认 | 作用 |
|---|---|---|
| `mouseSmoothing` | 0.45 | 输入阻尼；0 = 最灵敏、0.9 = 明显顺滑 |
| `sensX` / `sensY` | 1 / 1 | 水平/垂直灵敏度倍率 |
| `pivotSmoothTime` | 0.06 s | 只有"车在动"时生效，不影响鼠标转动 |
