## 4. ⚠️ 卡住的 bug：炮弹打不中

### 现象

抛物线弹道版本下，**打 200 m 外的静止目标也打不中**，炮弹飞过去就没了。三层伤害公式本身是对的（直线版实测过 194 伤害）。

### 已排查到的线索

| 检查 | 结果 |
|---|---|
| 弹道解算 | ✅ 正确：205 m / 160 m/s → 仰角 0.87°，全程离地 2.8~6.6 m（不会撞土包） |
| 沿弹道射线检测 | ❌ **`Physics.RaycastAll` 沿弹道打 210 m 返回 0 个命中**（连目标车体都没打到） |
| 目标碰撞体 | ✅ 存在且 enabled：BoxCollider center(−519,18.8,34.2) size(3.4,2.8,8.7)，瞄准点在其包围盒内 |
| 炮口位置 | ⚠️ **在自己车体的 BoxCollider 内部**（射线从炮口出发 4 m 处才打出自己车） |
| 命中日志 | ❌ 开了 `Projectile.DebugHits` 后**一条命中日志都没有**，说明炮弹从未命中任何东西 |

### 已做但没解决的修复

1. `PushOutsideOwnCollider()`：出膛点沿发射方向推到自身碰撞盒外（0.5 m 一步，最多 20 m）
2. `Projectile.DebugHits` 开关：打印命中物 + 每 12 帧位置

### 建议的下一步（按可疑度排序）

1. **先看 DebugHits 的位置日志**：开 play、打一发、看 `[Shell] pos=...` 每 12 帧的位置是否朝目标飞。如果位置正常但没命中 → 是碰撞检测问题；如果位置乱 → 是方向问题。
2. **退回直线弹道验证**：把 `VehicleCombat.BallisticDir` 的返回值改成 `(aim - origin).normalized`，如果直线能中（之前能中），说明问题在弹道解算或出膛点偏移。
3. **怀疑点**：`Fire()` 里 `dir` 是用**旧 origin（炮口）**算的，然后 origin 被推到盒子外再 `+dir*1`，弹道解算的起点和实际起点差了 3~5 m。近距离影响小，但值得统一。
4. **另一个怀疑**：`RaycastAll` 从碰撞体内部出发时，Unity 不返回该碰撞体，但**可能把后面的命中顺序搞乱**。可以改成从"出膛点 + dir × 5 m"开始检测。
5. 兜底方案：**改回直线弹道 + 抬高出膛点**（牺牲一点真实感，换取命中可靠）。

## 8. 这次踩的坑（新增，都别再踩）

| 坑 | 现象 | 修法 |
|---|---|---|
| **改完 .cs 立刻在同一个 MCP 调用里跑** | 跑的是旧程序集，白等 6 分钟 | `ImportAsset` 单独一次调用，等编译完再跑业务 |
| **场景里的私有字段丢值** | AI 阵营全变 0 | 要跨场景保存的字段必须是 public / [SerializeField] |
| **AI 重规划后路点 0 在车后** | AI 原地绕圈 | 跳过路点 0 + 越过判定（路点在身后就换下一个） |
| **直瞄弹道被地形挡** | 200 m 外打不中 | 改抛物线（当前有命中 bug，见第 4 节） |
| **编辑器帧率不代表真实** | 编辑器 65 FPS，打包 95 FPS | 用 `PerfProbe` 在 exe 里测 |
| **`FindObjectsByType` 默认不含未激活物体** | 车死了就找不到 | 传 `FindObjectsInactive.Include` |
| **PowerShell 传 JSON 给 bsk** | 引号被吞，解析失败 | 用反引号转义 `` "{\`"k\`":\`"v\`"}" `` |
| **网页有实时倒计时时 bsk 动作被拒** | "observation changed" | 用 `bsk step` 原子操作 + `--depends-on` 锁定区域 |
