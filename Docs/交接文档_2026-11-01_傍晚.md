## 3. 重坦履带为什么最后用了主战的几何（重要，别再重复试）

**重坦自己的 Lux3D 履带模型结构是坏的**：把代码全摘掉、只看原始 FBX 也是碎的。

- **三角面汤**：1790 个连通块，每块只有 3 个顶点（顶点完全不共用）。主战那套是焊接过的（18091 → 7328）
- **履带是薄片**：不是一块块履带板，是一圈薄带子，边上还挂着零散面片

返工 3 次（共 90 积分）的结果：

| 版本 | 结果 | 能不能用 |
|---|---|---|
| v2（面数 10 万） | 网格质量明显变好 | ✗ **只有一条履带**（宽度分布单峰） |
| v3（硬写"两条带 + 中间 3 米间隙"） | 两条带、间隙大 | ✗ **比例崩**：3.5×3.88×3.04，缩到 10 m 会变成 11.2 宽 × 8.8 高 |
| v4（写死**长宽高比例 3.5:1.9:1**） | **模型本身完全正确**：两条带、真空隙、比例 3.34:1.67:1、网格焊接 | ✗ **进 Unity 逐顶点动画就撕开**（网格里杂面太多） |

**教训**：让 Lux3D 生成履带，**写比例比写绝对尺寸有效**（v4 就是这么成的）；但模型好不好 ≠ 能不能做逐顶点动画。

**如果还要重坦独立**，建议换思路：**不要逐顶点动这条履带**，改用 `TrackScroller`（滚 UV）——外观损失小，但不会再撕。

## 5. 这一轮踩的坑（都别再踩）

| 坑 | 现象 | 修法 |
|---|---|---|
| **改了代码没生效，还以为"效果不明显"** | 编译报 `CS0136`（复用变量名 `k`），程序集没更新，渲染出来和上次一模一样 | **改完立刻查 console 有没有 Error**；`ImportAsset(ForceUpdate)` + `RequestScriptCompilation` 之后等 45~50 s 再验证 |
| **Blender 里量包围盒用网格局部坐标** | 物体自带变换时 bbox 是错的（以为 3.02 m，实际不是） | 量尺寸要 `o.matrix_world @ Vector(c)`，或者干脆在 Unity 里量 |
| **压扁放在轮子识别之前** | 圆轮压成椭圆，轮子从 13 个掉到 9 个 | 高度对齐必须放在导出前最后一步 |
| 只换 `mr.sharedMaterial` | 多 submesh 的网格只有第 0 块会变，其它还挂在旧材质上 → 那部分不跟着动 | 用 `mr.sharedMaterials` 全填 |
| 打包时编辑器停在临时场景 | `BuildPipeline.BuildPlayer` 返回 `Unknown` / 0 MB | 先 `OpenScene` 正式场景再打包 |
| ZapSplat 的坦克履带音 | 全是 **Access Premium Content**，免费账号下不到（实地登录确认） | 换 OpenGameArt / 自己从视频抠 |
| `bsk` 守护进程起不来 | `os error 5`（Job Object breakaway 被拒） | 用 `run_in_background: true` 跑 `bsk daemon start --foreground`，再 `BSK_AUTO_START=0 bsk status --json` |
